# Ponytail audit — 2026-08-10

## Scope and method

The original audit was static-only. Eight read-only reviewers ran in parallel
at luna/max effort over overlapping production slices. The existing dirty
worktree was preserved.

The final whole-repository challenge pass found no material new candidate. A
subsequent requested repair resolved every promoted finding below. Evidence in
the table describes the pre-repair code.

## Conditional candidates held for proof or product choice

- `DynamicRenderer` serializes every response-body read through `WorkPermitPool(1)` to make the shared byte budget atomic (`DynamicRenderer.ts:160-176,641-669`). Chunk-level synchronous reservation could preserve the cap and restore the documented four-way body concurrency, but no representative throughput evidence exists. Keep the semaphore until that measurement and a reservation contract exist; retain `WorkPermitPool` for cancellable subrequest/PDF admission. Affected: `DynamicRenderer.ts`, `responseBody.ts`; confidence: medium.
- `CrawlRuntime.awaitStartupStep` has one caller and wraps an already abort-aware initializer (`CrawlRuntime.ts:146-169,438-440`). Direct awaiting is smaller, but the current wrapper may intentionally preserve stop-error identity/race precedence. Remove only after a focused static/lifecycle proof settles that contract. Affected: `CrawlRuntime.ts`; confidence: medium.
- `ResumeSessionsPanel.shortenUrl` is custom, but it intentionally removes scheme/query and displays a hostname/path policy; CSS `truncate` cannot reproduce that policy (`ResumeSessionsPanel.ts:35-44,169-170`). Keep unless product chooses to display the full URL. Affected: `ResumeSessionsPanel.ts`; confidence: low for removal.
- SSE event fields are structurally unbounded and terminal frames bypass the pending queue cap (`shared/contracts/schemas.ts:216-249`, `server/plugins/sse.ts:48-85`). The final challenge pass found current runtime-generated terminal text bounded and did not promote a failure. Define a byte contract only if error text becomes user-controlled or a bounded-payload requirement is adopted. Affected: shared event schemas, `EventStream.ts`, `plugins/sse.ts`; confidence: conditional.
- Structured error logging could preserve Pino `err`/cause fields instead of stringifying at `server/errorHandling.ts:41-48`; this is an observability improvement, not unnecessary custom infrastructure, so it is not promoted here. Affected: `server/errorHandling.ts`, logger boundary; confidence: high for improvement, out of ponytail scope.
- Open object schemas omit `additionalProperties: false`; whether that is a defect depends on the repository's forward-compatibility policy, so it remains a contract decision rather than a ponytail cut. Affected: `shared/contracts/schemas.ts`, API/persistence boundaries; confidence: policy-dependent.

## Retained custom owners and dependencies

No replacement is justified for the following: pinned DNS/SSRF redirects and
cookie handling; `WorkPermitPool`'s cancellable FIFO leases; runtime/event-stream
replay and caps; crawl queue/admission/domain-delay policy; current-schema replacement,
statement finalization, SQLite FTS5 and storage reclamation; streaming JSON/CSV
export with CSV-injection protection; Cheerio, PDF.js, Playwright, `franc`,
`ipaddr.js`, `lru-cache`, `robots-parser`, `tough-cookie`, and Pino. The Elysia
patches and `exact-mirror` peer dependency are justified by the installed beta
package boundary and have an explicit upstream-removal policy in
`patches/README.md`/`bunfig.toml`.

## End state

All P-01 through P-19 findings are resolved. P-13 uses explicit
`credentials: false` because focused integration proof showed that the
installed CORS beta defaults credentials to true. P-15 removes the redundant
index from the single current schema; incompatible databases reset and the
retained primary-key lookup is verified directly.

The original repair closure passed `bun run check`, including a warning-free
production build. The follow-up closure passed typechecking, Biome, and targeted
owner-boundary tests for the changed runtime, API, storage, renderer, processor,
shared-contract, and UI paths. The full suite and production build were not
repeated under the follow-up's lightweight-validation constraint.
